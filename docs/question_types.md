# 공공조달관리사 문항 유형 계약

이 문서는 `questions.v2.json` 생성 프롬프트와 앱 렌더링이 공유하는 문항 유형 정의다. 공개 예제문제 6문항과 출제기준 매핑표를 기준으로 한다.

## 공통 필드

- `type`: 아래 유형 중 하나.
- `prompt`: 수험자가 직접 보는 질문 문장. 부정형이면 "아닌 것", "거리가 먼 것", "규정하고 있지 않은 것"처럼 부정 단서를 명확히 둔다.
- `choices`: 객관식 4개 선택지. 앱에서 보기 순서는 섞일 수 있으므로 해설은 선택지 텍스트 기준으로 작성한다.
- `answerIndex`: 정답 선택지 인덱스. 공개 예제문제는 정답 미제공이므로 `null`을 허용하지만, 최종 문제은행은 반드시 숫자여야 한다.
- `curriculumTag`: `S{과목}.M{주요항목}.SB{세부항목}.D{세세항목}` 형식의 세세항목 태그.
- `sourceExcerpt`: 최종 문제은행에서는 문제 생성 근거가 된 원문 일부.
- `sourceRef`: 최종 문제은행에서는 `skills/subject-*/chapters/*.md#anchor` 형식의 근거 위치.

## 유형

### `positive`

개념·절차·제도에 대한 올바른 설명을 고르는 기본형이다.

- 정답은 근거 chunk의 핵심 문장을 재구성한다.
- 오답은 유사 제도, 적용 범위 과장, 절차 생략, 최저가 단정처럼 시험장에서 자주 혼동되는 패턴으로 만든다.
- 문장 길이는 선택지 간 비슷하게 맞춘다.

### `negative`

"거리가 먼 것", "아닌 것", "규정하고 있지 않은 것"을 묻는 부정형이다.

- `prompt`에 부정 단서를 한 번만, 분명하게 쓴다.
- 정답은 해당 제도의 장점·요건·명시사항이 아닌 항목이다.
- 오답 3개는 실제 근거 문장과 맞는 항목이어야 한다.
- 해설 첫 문장은 "이 문제는 부정형이다"라고 알려도 된다.

### `concept-diff`

해제/해지/철회/취소처럼 비슷한 개념을 구별하는 유형이다.

- `prompt`는 정의 또는 효과를 제시하고 해당 용어를 고르게 한다.
- 선택지는 같은 법령 영역 안에서 헷갈릴 만한 용어로 구성한다.
- `wrongReasons`에는 각 용어가 왜 다른지 한 문장씩 적는다.

### `numeric`

기간, 금액, 기준 비율, 문항 수처럼 숫자 암기가 필요한 유형이다.

- 숫자 선택지는 단위까지 포함한다.
- 오답 숫자는 실제 수험자가 혼동할 수 있는 가까운 값으로 만든다.
- `sourceExcerpt`에 숫자와 단위가 함께 보여야 한다.

### `box-multi`

ㄱ, ㄴ, ㄷ 지문 중 해당하는 것을 모두 고르는 다중선택형이다.

- `choiceGroups`에 ㄱ, ㄴ, ㄷ 지문 텍스트를 순서대로 넣는다.
- `choices`는 "ㄱ, ㄴ", "ㄱ, ㄷ", "ㄴ, ㄷ", "ㄱ, ㄴ, ㄷ" 같은 조합 선택지다.
- 앱은 `choiceGroups`를 별도 박스로 렌더링하고, 선택지는 일반 4지선다와 동일하게 처리한다.
- 정답 조합 외 선택지도 모두 그럴듯해야 한다.

### `box-blank`

조문·규정·기준 문장을 박스로 제시하고 빈칸을 채우는 유형이다.

- `boxContext`에 빈칸이 포함된 원문형 문장을 넣는다.
- 빈칸은 `( )` 또는 `(     )`로 표시한다.
- 정답 선택지는 빈칸에 정확히 들어갈 숫자, 용어, 문구다.
- `sourceExcerpt`는 빈칸 처리 전 원문에 가까워야 한다.

## 렌더링 규칙

- `boxContext`가 있으면 질문 아래 인용 박스로 표시한다.
- `choiceGroups`가 있으면 ㄱ, ㄴ, ㄷ 라벨을 붙여 지문 목록을 표시한다.
- 선택지는 항상 4개를 기본으로 한다.
- 해설에서는 정답 근거, 오답별 이유, 출처를 순서대로 보여준다.
